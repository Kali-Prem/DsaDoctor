Chapter 01

🌟 5 Golden Rules (Dimag Me Baitha Lo)

Har coding session shuru karne se pehle ye 5 mental principles hamesha yaad rakho:

Rule 01

🚫 Code Se Pehle Logic

Keyboard tab chhuo jab paper pe pata ho ki exact kya likhna hai. Code sirf logic ka syntax translation hota hai.

💡 10 min pen-paper = 1 hour debug save
Rule 02

🪜 Seedha Optimal Nahi Aata

Pehle working brute force banao, safety net tayar karo. Uske baad bottleneck dekh kar right data structure lagao.

💡 Safety net first, speed second
Rule 03

🧪 Test Case Sabse Bada Hint Hai

Input se output kaise bana, haath se pen-paper pe trace karke dekho. Insaan jo step karta hai, wahi algorithm hai.

💡 Human intuition translates to code
Rule 04

⏱️ Constraints Batate Hain Technique

Problem ka n kitna bada hai, wahi bata deta hai kaunsa algorithm chalega. Input size se pehle hi complexity fix ho jati hai.

💡 N ≤ 10⁵ means O(N log N) max
Rule 05

🔁 Pattern Purana Hota Hai

DSA me ginke sirf 15–20 fundamental patterns hote hain. Problem statement badalta hai, underlying pattern hamesha same rehta hai.

💡 Focus on 20 core patterns, not 500 questions

Chapter 06

🪜 The Thinking Ladder & Waste Elimination Matrix

Jab brute force ready ho jaye, to dekho ki brute force me kya waste (redundancy) hai. Waste identify karke hi right tool lagta hai:

Brute Force Me Kya Waste Ho Raha Hai? Sahi Tool / Technique Resulting Speed
Linear search me baar-baar same check ho raha hai 🗂️ HashMap / HashSet O(n²) ➔ O(n)
Range [i..j] ka sum baar-baar calculate ho raha hai ➕ Prefix Sum Array O(n) query ➔ O(1) query
Sorted array me pairs search karne ke nested loops hain ↔️ Two Pointers (Left/Right) O(n²) ➔ O(n)
Subarray/Substring me redundant overlapping checks hain 🪟 Sliding Window O(n²) ➔ O(n)
Range sorted hai aur condition monotonic (T/F) hai 🎯 Binary Search on Answer O(n) ➔ O(log n)
Next greater / previous smaller element dhoondna hai 🥞 Monotonic Stack O(n²) ➔ O(n)
Running stream me Kth largest / smallest chahiye 🏔️ Min-Heap / Max-Heap O(n log n) ➔ O(n log k)
Same subproblems recursion me baar-baar recompute ho rahe hain 📊 Dynamic Programming (Memo/Table) O(2ⁿ) ➔ O(n) ya O(n²)

Chapter 08

🆘 "Jab Atak Jao To Kya Karo" (Live Troubleshooting)

Interview me jab dimag blank ho jaye ya test case fail ho rahe hon, to ye emergency checklist use karein:

Situation 1

🤯 Kuch Samajh Nahi Aa Raha?

Sabse chhota test case (2-3 elements) lo aur haath se pen-paper pe trace karo. Insaan jaise answer nikalta hai, wahi algorithm hai.

Situation 2

🔨 Brute Force Ban Gaya, Optimize Nahi Ho Raha?

Waste dhoondo: Loop ke andar kya redundant repeat ho raha hai? Search repeat ho raha hai to Map lagao, Range sum repeat ho raha hai to Prefix Sum.

Situation 3

⏱️ TLE (Time Limit Exceeded) Aa Raha Hai?

Complexity calculate karo. 10⁵ pe O(N²) TLE dega hi. Sorting + Binary Search ya Hashing lagakar O(N log N) ya O(N) me lao.

Situation 4

🐛 Corner Case Pe Code Fat Raha Hai?

Check karo: Empty array, single element, negative numbers, all duplicates, integer overflow (Integer.MAX_VALUE), 0 division.
